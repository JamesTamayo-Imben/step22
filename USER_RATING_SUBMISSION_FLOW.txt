================================================================================
                   HOW USERS SUBMIT RATINGS - COMPLETE FLOW
================================================================================
PROJECT: User Rating Submission System
CREATED: 2026-06-21
PURPOSE: Documents the entire flow from UI to database for rating submission

================================================================================
                            QUICK OVERVIEW
================================================================================

USER JOURNEY:
  1. Student/User opens a project details page
  2. User sees a "Rate Project" button
  3. User clicks button to open rating modal
  4. User fills in:
     - Satisfaction Rating (1-5 stars)
     - Completeness Rating (1-5 stars)
     - Engagement Rating (1-5 stars)
     - Comment (optional text)
  5. User clicks "Submit Rating"
  6. Frontend sends POST request to backend
  7. Backend validates and stores rating in database
  8. Page reloads to show success
  9. Rating becomes visible in Analytics Dashboard

SCHEMA:
CREATE TABLE `ratings` (
  `id` char(36) NOT NULL,               -- UUID primary key
  `project_id` char(36) DEFAULT NULL,   -- Foreign key to projects
  `user_id` char(36) DEFAULT NULL,      -- Foreign key to users
  `rating_score` int(11) DEFAULT NULL,  -- 1-5 stars
  `comments` text DEFAULT NULL,         -- Optional feedback
  `helpful_count` int(11) DEFAULT 0,    -- Vote count on this rating
  `created_at` timestamp NOT NULL DEFAULT current_timestamp(),  -- Submission time
  `archive` tinyint(1) DEFAULT 0        -- Soft delete flag
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

FOREIGN KEY CONSTRAINTS (Lines 1003-1004):
  ratings_ibfk_1: project_id → projects(id) ON DELETE CASCADE
    - If project deleted, this rating deleted automatically
  
  ratings_ibfk_2: user_id → users(id) ON DELETE SET NULL
    - If user deleted, user_id set to NULL (preserves rating data)

================================================================================
                          ERROR SCENARIOS & RESPONSES
================================================================================

SCENARIO 1: User Not Authenticated
  Status: 401 Unauthorized (by auth middleware)
  User redirected to login
  PURPOSE: Prevent unauthenticated rating submissions

SCENARIO 2: Invalid Project ID
  Status: 404 Not Found
  Message: (Laravel default not found response)
  Cause: Project doesn't exist or is archived
  PURPOSE: Prevent rating non-existent projects

SCENARIO 3: Project Not Approved
  Status: 422 Unprocessable Entity
  Message: "Project is not approved for public ratings"
  Cause: Project approval_status !== 'Approved'
  PURPOSE: Enforce only rating approved projects

SCENARIO 4: Rating Score Invalid
  Status: 422 Unprocessable Entity
  Message: Contains validation errors (e.g., "rating must be between 1 and 5")
  Cause: rating < 1 or > 5, or not integer, or missing
  PURPOSE: Ensure data quality

SCENARIO 5: Comment Too Long
  Status: 422 Unprocessable Entity
  Message: Contains validation errors (e.g., "comment may not be greater than 1000 characters")
  Cause: Comment string length > 1000
  PURPOSE: Prevent database overflow

SCENARIO 6: User Already Rated This Project
  Status: 422 Unprocessable Entity
  Message: "You have already rated this project. You can only rate once per project."
  Cause: Existing rating found for this user + project combination
  PURPOSE: Enforce one-rating-per-project rule

SCENARIO 7: Network Error During Submission
  Frontend: Error caught in catch block
  Console: Error logged to developer console
  UI: Button remains disabled, no message shown to user
  PURPOSE: Prevent silent failures

================================================================================
                            IMPORTANT CONSTRAINTS
================================================================================

ONE RATING PER USER PER PROJECT:
  - User can only submit one rating per project
  - Enforced in Controller at line 260-267
  - Database can have multiple ratings from same user if for different projects
  - Database can have multiple ratings for same project from different users

RATING SCALE:
  - Must be integer 1-5 (inclusive)
  - Validated in Controller at line 250
  - No half-stars (e.g., 3.5) allowed
  - No zero or negative ratings allowed

COMMENT OPTIONAL BUT LIMITED:
  - Comment can be null/empty
  - If provided: must be string, max 1000 characters
  - Comment stored as TEXT in database (can handle long comments)
  - Special characters (quotes, newlines) properly escaped by ORM

PROJECT MUST BE APPROVED:
  - Only 'Approved' projects can be rated
  - Enforced in Controller at line 257-258
  - Draft, pending, or rejected projects cannot be rated
  - Prevents rating unfinished projects

USER MUST BE AUTHENTICATED:
  - Requires login (auth middleware)
  - Requires verified account (verified middleware)
  - Requires user role (role:user middleware)
  - System knows exact user ID from session

NO RATING UPDATES ALLOWED:
  - Current implementation only allows INSERT (new ratings)
  - Controller checks if rating exists and rejects if found
  - If user wants to change rating: must use API differently
  - Or ratings must be soft-deleted and recreated


================================================================================
                          HOW DATA FLOWS TO ANALYTICS
================================================================================

1. USER SUBMITS RATING
   └─ Rating stored in ratings table

2. ADVISER VISITS /adviser/ratings
   └─ AdviserRatingsController::index() called

3. CONTROLLER QUERIES RATINGS TABLE
   └─ Fetches all non-archived ratings for approved projects

4. AGGREGATION HAPPENS:
   ├─ Counts total ratings per project
   ├─ Calculates average rating_score per project
   ├─ Builds rating distribution (5★, 4★, 3★, 2★, 1★)
   ├─ Analyzes trends (last 30 vs 30-60 days)
   └─ Calculates KPIs (overall average, satisfaction rate)

5. DATA TRANSFORMED FOR FRONTEND:
   ├─ projectSummaries: Array of project stats
   ├─ studentRatings: Array of individual ratings
   └─ kpi: Overall metrics

6. RENDERED IN DASHBOARD:
   ├─ KPI Cards show aggregate statistics
   ├─ Project Cards show per-project stats
   ├─ Star distributions show breakdown
   └─ Comments display shows recent feedback
