# Bulk User Registration - Quick Reference

## How It Works (Admin Perspective)

### Step 1: Open Modal
- Go to User Management (`/sadmin/users`)
- Click "Create User" button

### Step 2: Select Role & Type
Choose from available roles (Student, Teacher, etc.) and select:
- **Single**: Register one user
- **Multiple**: Register up to 10 users

### Step 3: Enter Information
- **Single**: Name and Email
- **Multiple**: Paste emails (one per line), optionally with names
  ```
  juan@kld.edu.ph
  Maria Santos maria@kld.edu.ph
  professor@kld.edu.ph
  ```

### Step 4: Submit
Click "Create & Send Invitations"
- System creates users
- Auto-generates passwords
- Sends invitation emails
- Users appear in table with status "active"

## How It Works (User Perspective)

### Step 1: Receive Email
- Subject: "Welcome! Complete Your Registration"
- Contains:
  - Their email address
  - Auto-generated password (e.g., `juanKLD2026`)
  - Role-specific signup link

### Step 2: Click Link
- Opens role-specific signup page (teacher or student)
- Pre-filled data visible:
  - Email
  - Initial password
  - Name (if provided)

### Step 3: Complete Profile
- Teacher: Add employee ID, specialization, office
- Student: Add student ID, year level, contact
- Click "Complete Registration"

### Step 4: Login
- Use email and password from invitation
- **Important**: Change password immediately after first login

## Password Format

```
[username from email] + KLD + [current year]
```

Examples:
- `lpcalibuso@kld.edu.ph` → `lpcalibusoKLD2026`
- `juande@kld.edu.ph` → `juandeKLD2026`
- `astudent@kld.edu.ph` → `astudentKLD2026`

## URLs

### Admin Access
```
GET /sadmin/users (User Management page)
```

### Public Signup Pages
```
GET /auth/register-teacher?email=...&password=...&name=...
GET /auth/register-student?email=...&password=...&name=...
```

### API Endpoints
```
POST /api/auth/register-teacher
POST /api/auth/register-student
POST /sadmin/users/bulk-create (admin only)
```

## Validation Rules

### Single Registration
- ✅ Name required
- ✅ Email required, must be unique
- ✅ Valid email format

### Multiple Registration
- ✅ At least 1 email
- ✅ Max 10 emails per request
- ✅ All emails must be unique
- ✅ Valid email format

### Teacher Signup
- ✅ First Name required
- ✅ Last Name required
- ✅ Employee ID required, must be unique
- ✅ Email auto-filled (cannot change)
- ✅ Password auto-filled (for reference)

### Student Signup
- ✅ First Name required
- ✅ Last Name required
- ✅ Student ID required, must be unique
- ✅ Year Level required (1st, 2nd, 3rd, 4th)
- ✅ Email auto-filled (cannot change)
- ✅ Password auto-filled (for reference)

## Email Content

The invitation email includes:

1. **Welcome Message**
   ```
   Hello [Name]!
   Your account has been created and is ready to use.
   ```

2. **Credentials Box**
   ```
   Email: [email@kld.edu.ph]
   Password: [autoGeneratedKLD2026]
   ```

3. **Security Warning**
   ```
   ⚠️ Important: Please change this password immediately 
   after your first login for security.
   ```

4. **Role Badge**
   ```
   [Teacher/Student]
   ```

5. **Instructions**
   1. Click the button to start registration
   2. Use the email and password provided
   3. Complete profile information
   4. Change password to something secure
   5. Start using the platform

6. **CTA Button**
   - Links to role-specific signup page
   - Includes email, password, name in URL

## Troubleshooting

### Issue: "Maximum 10 emails allowed"
- **Cause**: Trying to register more than 10 users at once
- **Solution**: Split into multiple batches

### Issue: "User with email X already exists"
- **Cause**: Email is already registered in system
- **Solution**: Use different email or check user exists in User Management

### Issue: Email not received
- **Cause**: Email service misconfigured or delivery failed
- **Solution**: Check MAIL_* env variables, verify email in user list (user created successfully)

### Issue: "Employee ID already exists" / "Student ID already exists"
- **Cause**: ID already used by another user
- **Solution**: Use different ID number

### Issue: Pre-filled password not visible on signup page
- **Cause**: URL parameters not passed correctly
- **Solution**: Click link in email or paste full URL with parameters

## Security Notes

✅ **Secure by default:**
- Passwords hashed in database
- Email sent via secure MAIL service
- CSRF token required for API calls
- Validation on all inputs
- UUID for user IDs (prevents guessing)

⚠️ **Important reminders:**
- Auto-generated passwords sent via email (standard practice)
- Users must change password after first login
- Admin should only share signup links via official email
- Don't share credentials in chat/messages

## Support

If you encounter issues:
1. Check error message in admin modal
2. Look at recent users in User Management table
3. Check email logs: `storage/logs/laravel.log`
4. Verify MAIL configuration in `.env`
5. Test API endpoint directly with curl/Postman
