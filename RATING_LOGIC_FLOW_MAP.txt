TREND CALCULATION (Controller Line 47-57):
  Recent: ratings from now to -30 days
  Older: ratings from -30 days to -60 days
  avgRecent = recent.avg('rating_score')
  avgOlder = older.avg('rating_score')
  trendValue = avgRecent - avgOlder
  
  IF trendValue > 0.05: trend = 'up'      (5% improvement)
  ELSE IF trendValue < -0.05: trend = 'down' (5% decline)
  ELSE: trend = 'stable'

  distribution[s] = count of ratings where floor(rating_score) == s

================================================================================
                          WHY THIS ARCHITECTURE?
================================================================================

1. SEPARATION OF CONCERNS:
   - Database: Raw data storage with constraints
   - Model: ORM layer for type safety and relationships
   - Controller: Business logic (aggregation, calculations)
   - Route: URL mapping and middleware
   - Component: UI rendering and user interaction

2. PERFORMANCE OPTIMIZATION:
   - Server-side aggregation reduces client-side work
   - Eager loading (project, user) prevents N+1 queries
   - useMemo prevents unnecessary re-renders
   - Client-side filtering (no extra DB queries)

3. SECURITY:
   - Server validates which projects/ratings to show
   - User names masked in display (maskUserName)
   - Archive flag allows soft deletes
   - Foreign key constraints maintain referential integrity

4. SCALABILITY:
   - Stateless controller handles any user's ratings
   - Can add caching at controller level
   - Client-side filtering scales to thousands of ratings
   - Database indexes on project_id, user_id, created_at

5. USER EXPERIENCE:
   - Rich filtering (project, rating, date, search)
   - Real-time sorting and search
   - Data export to CSV
   - Trend indicators show progress
   - Comments show qualitative feedback
